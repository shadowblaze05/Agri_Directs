AGRI-DIRECT SYSTEM DOCUMENTATION
================================

OVERVIEW
--------
Agri-Direct is a Flask-based web application for managing agricultural harvest postings, providing real-time inventory analytics, location-based tracking, and basic messaging between users. Farmers can upload harvest data (CSV or manual entry), buyers can browse and purchase inventory, and admins manage users and data.

This documentation describes the current implementation (as of July 15, 2026): routes, data model, deployment notes, environment variables, frontend behavior, and testing pointers.

SYSTEM ARCHITECTURE
-------------------
- Backend: Flask (single-module app in `app.py`)
- Database: SQLite (`database.db`), accessed via `sqlite3` with `row_factory` set to `sqlite3.Row`
- Frontend: Server-rendered Jinja2 templates, Bootstrap 5, Chart.js and Leaflet (CDN)
- Authentication: Session-based (Flask session) for web UI; JWT for API access
- Real-time Updates: Client-side AJAX polling (dashboard refresh every 2 seconds) using `/dashboard-data` and `/api/stats`
- Geocoding: Optional Google Maps Geocoding API; otherwise deterministic fallback coordinates

ALGORITHM 1: REAL-TIME MARKET PRICE MONITORING
----------------------------------------------
The system aggregates inventory data and evaluates current supply against historical averages and recent trend movement. A price index is computed to represent market pressure.

Logic:
- Calculate total supply per crop
- Calculate average supply from historical entries
- Compare current supply with the average supply
- Measure trend change using the difference between recent periods
- Generate a price index using the formula:
  price_index = 100 + (supply_pressure * 8) + (trend_change * 25) - 10

ALGORITHM 2: OVERSUPPLY AND UNDERSUPPLY RISK DETECTION
--------------------------------------------------------
The system uses threshold-based evaluation to identify possible market imbalance.

Logic:
- If current supply is much higher than the recent average, the crop is flagged as an oversupply risk.
- If current supply is much lower than the recent average, the crop is flagged as an undersupply risk.

Thresholds used in the implementation:
- Oversupply risk if supply_pressure >= 1.35
- Undersupply risk if supply_pressure <= 0.75

ALGORITHM 3: CROP RECOMMENDATION SYSTEM
----------------------------------------
The crop recommendation system uses a weighted scoring model based on demand level, price pressure, and seasonal relevance.

Weighted formula:
recommendation_score = (demand_score * 0.45) + ((price_index - 80) / 100 * 0.35) + (seasonal_score * 0.20)

The system calculates:
- demand_score from supply pressure
- price_index from market pressure and trend movement
- seasonal_score based on predefined seasonal suitability for each crop

ALGORITHM 4: CROP DEMAND FORECASTING
------------------------------------
The demand forecasting module uses a simple linear trend model based on historical inventory data.

Forecast formula:
forecast = intercept + slope * n

Implementation details:
- Historical values are collected over time
- The slope and intercept are computed from the trend line
- The next period forecast is estimated and displayed in the Market Intelligence page

PROGRAMMING CODE USED
---------------------
The current implementation uses the following core code in `app.py`:

```python
def _linear_forecast(values):
    if not values:
        return 0
    if len(values) < 2:
        return max(0, int(values[-1]))

    x_values = list(range(len(values)))
    mean_x = sum(x_values) / len(x_values)
    mean_y = sum(values) / len(values)
    numerator = sum((x - mean_x) * (y - mean_y) for x, y in zip(x_values, values))
    denominator = sum((x - mean_x) ** 2 for x in x_values)
    slope = numerator / denominator if denominator else 0
    intercept = mean_y - slope * mean_x
    forecast = intercept + slope * len(values)
    return max(0, int(round(forecast)))
```

```python
def build_market_analysis(records):
    crop_totals = defaultdict(int)
    monthly_totals = defaultdict(int)
    crop_history = defaultdict(list)

    for row in records:
        crop_name = str(row["crop_name"] or "").strip()
        quantity = int(row["quantity"] or 0)
        if not crop_name or quantity <= 0:
            continue

        crop_totals[crop_name] += quantity
        month_key = _parse_inventory_datetime(row.get("date_received")).strftime("%Y-%m")
        monthly_totals[month_key] += quantity
        crop_history[crop_name].append((month_key, quantity))
```

SUMMARY
-------
These algorithms transform the system from a basic inventory platform into a decision-support tool for agricultural trading. They help farmers and buyers understand market conditions, detect risks, prioritize crop recommendations, and estimate future demand based on data.

CORE FEATURES (current)
-----------------------
- User registration and login (passwords hashed using Werkzeug)
- Roles: `admin`, `user` (default role assigned as 'user' or 'buyer' in UI)
- CSV upload (server-validated) and manual harvest entry
- Inventory CRUD (farmers can edit/delete own items; admins can edit/delete all)
- Real-time dashboard with charts (monthly/yearly summaries and comparisons)
- Persistent monthly analytics snapshots stored in the `analytics` table, including total harvest, top crop, top location, and related volumes
- Dashboard shows a month-by-month analytics history section populated from saved analytics rows
- `/api/stats` endpoint supports `monthly_offset` and `yearly_offset` to view previous periods
- Location analytics with Leaflet map using geocoded coordinates
- Simple chat system persisted in `messages` table; polling every 3 seconds when chat open
- JWT-protected API endpoint `POST /api/harvest` for external data ingestion

DATABASE SCHEMA
---------------
- `users`:
  - `id` INTEGER PRIMARY KEY AUTOINCREMENT
  - `username` TEXT UNIQUE
  - `password` TEXT (hashed)
  - `role` TEXT (defaults to 'user')
  - `location` TEXT (optional)

- `inventory`:
  - `id` INTEGER PRIMARY KEY AUTOINCREMENT
  - `crop_name` TEXT
  - `quantity` INTEGER
  - `farmer` TEXT (username)
  - `date_received` TEXT (stored as YYYY-MM-DD HH:MM:SS)
  - `location` TEXT (optional)

- `messages`:
  - `id` INTEGER PRIMARY KEY AUTOINCREMENT
  - `sender` TEXT
  - `recipient` TEXT
  - `message` TEXT
  - `timestamp` TEXT

- `analytics`:
  - `id` INTEGER PRIMARY KEY AUTOINCREMENT
  - `period_type` TEXT
  - `period_value` TEXT (for example `2026-07`)
  - `total_harvest` INTEGER
  - `top_crop` TEXT
  - `top_crop_volume` INTEGER
  - `top_crop_id` INTEGER
  - `top_location` TEXT
  - `top_location_volume` INTEGER

Notes on migrations:
- On startup `init_db()` ensures tables exist and will ALTER tables to add `recipient` (messages) and `location` (inventory) if missing.
- `update_analytics()` creates or updates monthly analytics rows and preserves historical monthly entries for the dashboard history view.

ROUTES / API (summary)
---------------------
Authentication & User Management
- GET `/`                       - Redirects to `/dashboard` if logged in, otherwise `/login`
- GET/POST `/login`              - Login form and processing
- GET/POST `/register`           - Register new user
- GET/POST `/profile`            - View/update user profile (location stored here)
- GET `/logout`                  - Logout (clears session)
- POST `/token`                  - Returns a JWT token for API use (expires in 24h)

Dashboard & Data
- GET `/dashboard`               - Dashboard page
- GET `/dashboard-data`          - Returns inventory table HTML (used for polling)
- GET `/api/stats`               - Returns JSON stats and summaries; supports query params `monthly_offset` and `yearly_offset` (integers >= 0)

Inventory Management
- GET/POST `/upload`             - Upload CSV or manual harvest entry
- GET/POST `/inventory/edit/<id>`- Edit inventory item (permission-checked)
- GET `/inventory/delete/<id>`   - Delete inventory item (permission-checked)
- GET `/admin`                   - Admin console (admin only)

Chat / Messages
- GET `/api/users`               - Returns list of other users plus special `AgriBot`
- GET `/api/messages?recipient=X`- Retrieve last 50 messages between current user and `X`
- POST `/api/messages`           - Send message to a recipient (stores and optionally replies if recipient==AgriBot)

API / External
- POST `/api/harvest` (JWT)     - Add harvest data programmatically. Requires `Authorization: Bearer <token>` header.

IMPLEMENTATION NOTES
--------------------
- Tokens: `generate_jwt_token(username)` issues HS256 tokens using `JWT_SECRET` environment variable.
- Authorization decorator `token_required` validates tokens for API endpoints.
- `geocode_location(location)` will use `GOOGLE_MAPS_API_KEY` if present; otherwise a deterministic fallback coordinate is computed.
- Uploads: CSV files must be UTF-8 and contain `crop_name` and `quantity` fields. Manual entries are also supported via form.
- Dashboard polling: client JS fetches `/dashboard-data` (HTML) and `/api/stats` (JSON) every 2 seconds to update UI.
- `/api/stats` returns top_monthly, top_yearly, monthly comparison arrays, labels for selected/previous periods.

DEPLOYMENT & RUNNING LOCALLY
----------------------------
1. Create and activate a virtualenv
   - Windows: `python -m venv .venv` then `.venv\Scripts\activate``
2. Install dependencies:
   - `pip install -r requirements.txt`
3. Initialize and run (development):
   - `python app.py` (the app calls `init_db()` and starts Flask with `debug=True`)
4. Open `http://127.0.0.1:5000` in a browser

SECURITY & LIMITATIONS (current)
--------------------------------
- Passwords are hashed using Werkzeug.
- API uses JWT tokens with expiration.
- SQL statements use parameterized queries to reduce injection risk.
- There is no explicit CSRF token implementation in `app.py` (Flask-WTF/CSRF is not used). If deploying publicly, add CSRF protection and review cookie settings.
- File uploads are validated for `.csv` extension and basic row validation; further sanitization is recommended for production.
